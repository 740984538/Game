## 阶段1：项目骨架搭建

**阶段目标**：能启动一个空白窗口，具备主循环、场景切换和事件总线基础框架

### 【阶段1-1】目录结构初始化
- **任务内容**：按架构文档创建完整目录树和空的 `__init__.py`
- **涉及文件**：`src/`, `config/`, `assets/`, `saves/`, `tests/`, `docs/` 各子目录
- **完成标志**：
  - 所有目录存在，包含空 `__init__.py`
  - `requirements.txt` 包含 pygame、esper、pyyaml、numpy 等依赖
  - `.gitignore` 忽略 `saves/`、`__pycache__/`、`*.pyc`

### 【阶段1-2】主循环
- **任务内容**：实现 `Game` 类，包含 pygame 初始化、主循环（update/render/事件派发）、帧率控制
- **涉及文件**：`main.py`, `src/core/game.py`
- **完成标志**：
  - 运行 `python main.py` 能打开指定分辨率的窗口
  - 主循环以目标帧率稳定运行
  - 关闭窗口能正常退出

### 【阶段1-3】状态机
- **任务内容**：实现 `StateMachine` 和 `BaseScene`，支持场景注册与切换
- **涉及文件**：`src/core/state_machine.py`
- **完成标志**：
  - `StateMachine.change(state)` 能切换场景
  - 触发 `old_scene.exit()` 和 `new_scene.enter(**kwargs)`
  - 每帧调用当前场景的 `update(dt)` 和 `render(surface)`

### 【阶段1-4】事件总线
- **任务内容**：实现 `EventManager`，支持发布/订阅解耦各系统
- **涉及文件**：`src/core/event_manager.py`
- **完成标志**：
  - `subscribe(event_name, callback)` 注册监听
  - `publish(event_name, **kwargs)` 触发所有监听回调
  - 支持 `unsubscribe` 取消监听

### 【阶段1-5】全局常量与枚举
- **任务内容**：定义 `GameState` 枚举、颜色/尺寸常量、`BuffType`/`Rarity` 等枚举
- **涉及文件**：`src/utils/constants.py`, `src/utils/enums.py`
- **完成标志**：
  - `GameState` 枚举包含所有场景状态（MAIN_MENU / COMBAT / GAME_OVER 等）
  - `Rarity` 枚举：common / rare / epic / legendary
  - `BuffType` 枚举包含后续系统所需的基础 buff 类型
  - 分辨率、帧率等常量集中在 `constants.py`

## 阶段7：Buff 系统

**阶段目标**：战斗中能施加和处理 Buff/Debuff，遗物与卡牌效果可依赖 Buff 机制

### 【阶段7-1】Buff 数据结构
- **任务内容**：定义 `Buff` 数据类，包含类型、层数/持续时间、来源
- **涉及文件**：`src/ecs/components.py`（BuffList 组件）, `src/utils/enums.py`（BuffType）
- **完成标志**：
  - `BuffType` 枚举包含：力量、虚弱、易伤、中毒、燃烧、格挡、再生等
  - `Buff` dataclass：`buff_type`, `stacks`（层数）, `duration`（回合数，-1为永久）
  - `BuffList` 组件持有实体当前所有 buff 列表

### 【阶段7-2】Buff 处理器
- **任务内容**：实现 `BuffProcessor`，每回合结束时衰减层数/持续时间并触发 tick 效果
- **涉及文件**：`src/systems/buff_system.py`
- **完成标志**：
  - 回合结束时遍历所有实体的 BuffList
  - 持续时间类 buff（如虚弱）每回合 duration -1，归零时移除
  - 层数类 buff（如中毒）每回合造成等于层数的伤害，然后 stacks -1
  - 燃烧每回合造成固定伤害
  - 已失效 buff 自动从列表移除

### 【阶段7-3】Buff 施加接口
- **任务内容**：提供统一的 `apply_buff` 工具函数，卡牌/遗物效果均通过此接口施加 buff
- **涉及文件**：`src/systems/buff_system.py`（或 `src/utils/helpers.py`）
- **完成标志**：
  - `apply_buff(entity_id, buff_type, value)` 接口统一
  - 相同 buff 叠加时合并层数（叠层型）或刷新持续时间（刷新型）
  - 施加 buff 后发布 `on_buff_applied` 事件

### 【阶段7-4】Buff 对战斗数值的影响
- **任务内容**：在伤害结算时读取 buff 状态修正数值（力量加伤、虚弱减伤、易伤增伤）
- **涉及文件**：`src/systems/combat_system.py`
- **完成标志**：
  - 力量：攻击伤害 +N（N为层数）
  - 虚弱：攻击伤害 ×0.75
  - 易伤：受到伤害 ×1.5
  - 格挡优先抵消伤害，多余格挡保留到下回合（每回合清空）

### 【阶段7-5】Buff UI 显示
- **任务内容**：在战斗场景中在实体血条下方显示当前 buff 图标和层数
- **涉及文件**：`src/scenes/combat_scene.py`, `src/systems/render_system.py`
- **完成标志**：
  - 玩家和敌人的 buff 以小图标+数字形式显示
  - 鼠标悬停 buff 图标时显示 tooltip（名称+说明）
  - buff 移除时图标消失

## 附录：开发建议

### 每个任务的推荐流程
1. **设计接口**：先定义类和方法签名
2. **实现功能**：编写核心逻辑
3. **本地测试**：在场景中临时测试
4. **集成验证**：与已有功能联调
5. **标记完成**：更新本文档状态

### 调试技巧
- 使用`print()`或日志输出关键流程
- 先用占位图/颜色代替美术资源
- 每个阶段完成后运行完整流程验证

### 文件命名规范
- UI组件：`src/ui/widgets/{组件名}.py`
- 场景：`src/scenes/{场景名}_scene.py`
- 系统：`src/systems/{系统名}_system.py`
- 实体：`src/entities/{类型}/{实体名}.py`
